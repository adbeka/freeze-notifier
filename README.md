# backend/ + status_page/ — вариант без исполнения кода на рабочей машине

Для случаев, когда PowerShell для обычных пользователей заблокирован
(даже неинтерактивно, даже через Планировщик заданий) — см. `onprem/`
для случая, когда PowerShell доступен.

## Идея

Никакого агента, никакого exe, никакого расширения браузера с инъекцией
в SDN-панель. На рабочей машине вообще не выполняется никакого кода,
кроме обычного просмотра веб-страницы в уже разрешённом браузере — то
же самое, что открыть любой внутренний корпоративный сайт.

```
[IT: admin/ - веб-форма] --пишет--> [backend: SQLite, внутри периметра компании]
                                              │
                                    отдаёт статус по HTTP, читает браузер
                                              ▼
                        [рабочая машина инженера: вкладка браузера status/]
                        → полноэкранный мигающий статус + звук
                        → системный Notification (нативный toast Windows)
                        → кнопка "Понял(а)" → лог подтверждений на сервере
```

Единственное отличие от исходного (отклонённого) варианта — backend
хостится **внутри периметра компании**, а не на стороннем PaaS (Railway),
и рядом с ним нет exe-агента и нет браузерного расширения. Сам backend не
был причиной отказа службы безопасности — отклонены были только
размещение вовне, exe и DOM-инъекция.

## Запуск

```bash
cd backend
python3 -m venv venv && source venv/bin/activate
pip install -r requirements.txt
FREEZE_API_KEY=<секрет-для-записи> uvicorn app.main:app --host 0.0.0.0 --port 8000
```

Разворачивать нужно на сервере **внутри сети компании** (не на внешнем
облаке) — например, на той же машине/ВМ, что уже используется под
внутренние сервисы ИТ-отдела.

## Что открывать кому

- **ИТ-администратор** (объявляет окна запрета): `http://<host>:8000/admin/`
  — нужен `X-API-Key`, вводится в поле на странице (сохраняется в
  localStorage браузера).
- **Инженер** (видит статус запрета): `http://<host>:8000/status/?segment=dept-ro`
  — без ключа, `segment` в адресе — тот сегмент/подразделение, к которому
  относится это рабочее место. Разные команды получают разные ссылки с
  разным `segment=`.

Эту вторую ссылку и нужно закрепить как домашнюю страницу или
закреплённую вкладку браузера через GPO (Chrome/Edge
`HomepageLocation` + `RestoreOnStartupURLs`, или Edge
`PinnedLaunchpadApps`) — тогда страница открывается автоматически при
каждом старте браузера, без каких-либо действий инженера.

## Страница статуса (status_page/index.html)

- Меняет цвет всей страницы (зелёный/красный/жёлтый), заголовок вкладки
  и favicon в зависимости от статуса — заметно даже если вкладка не в
  фокусе.
- Мигает (переключение оттенка раз в 600 мс), пока запрет активен или
  статус не подтверждён.
- Проигрывает короткий звук (Web Audio API) один раз, в момент когда
  запрет только начался — учтите, что браузеры могут блокировать
  автовоспроизведение звука без предварительного взаимодействия
  пользователя со страницей; это best-effort, а не гарантированный канал.
- Кнопка "Включить системные уведомления" запрашивает разрешение на
  `Notification` API — после этого статус дублируется нативным
  Windows-уведомлением через браузер, видимым даже если вкладка свёрнута
  или находится в фоне.
- Кнопка "Понял(а), не буду вносить изменения" — отправляет подтверждение
  на сервер (`POST /api/ack`), которое видно ИТ-администратору через
  `GET /api/acks` (с `X-API-Key`). Это аудиторский след: доказательство,
  что конкретный человек подтвердил, что видел активный запрет, а не
  просто "баннер где-то показывался".

## API

- `GET /api/status?segment=dept-ro` — публичный, читает страница статуса.
- `GET/POST/PUT/DELETE /api/windows` — управление расписанием (запись
  требует `X-API-Key`).
- `POST /api/ack` — публичный (подтверждение от инженера, не
  административное действие). Требует существующий `window_id`.
- `GET /api/acks?window_id=...` — список подтверждений, требует
  `X-API-Key`.

## Многопользовательский запуск (несколько человек одновременно)

Нагрузочный тест ([loadtest.py](loadtest.py)) подтвердил: после настройки
пула соединений в [database.py](app/database.py) сервер держит тысячи
одновременных запросов без отказов. Остаётся сама механика развёртывания —
всё ниже нужно на **выделенной внутренней Windows-машине**, не на чьём-то
личном ноутбуке.

### 1. TLS-сертификат (самоподписанный, для быстрого старта)

```bash
venv\Scripts\python generate_cert.py YOUR-SERVER-HOSTNAME
```

Создаёт `certs\cert.pem` и `certs\key.pem` (`certs/` в `.gitignore` —
приватный ключ никогда не должен попасть в git). `run.bat` и
`run-service.bat` сами подхватывают TLS на `:8443`, если файлы на месте;
без них — обычный HTTP на `:8000`, как раньше.

Самоподписанный сертификат не в доверенных у клиентов "из коробки" — на
каждой рабочей машине браузер будет показывать предупреждение, пока
сертификат не добавлен в доверенные (см. шаг 4). Для реальной
эксплуатации лучше заменить на сертификат, выпущенный внутренним CA
компании — тогда шаг 4 не нужен, GPO уже доверяет корневому CA.

### 2. Открыть порт в брандмауэре (на сервере, PowerShell от администратора)

```powershell
New-NetFirewallRule -DisplayName "Freeze Notifier" -Direction Inbound -Protocol TCP -LocalPort 8443 -Action Allow
```

(порт `8000`, если без TLS.)

### 3. Автозапуск при загрузке + автоперезапуск при сбое

Шаблон задачи — [deploy/FreezeNotifier.task.xml](deploy/FreezeNotifier.task.xml).
Перед импортом впишите в него реальный путь к `run-service.bat` (сейчас
там `C:\PATH\TO\backend\run-service.bat`), затем на сервере (PowerShell от
администратора):

```powershell
schtasks /Create /XML "C:\path\to\backend\deploy\FreezeNotifier.task.xml" /TN "FreezeNotifier"
```

`run-service.bat` — версия `run.bat` без `pause` и без переустановки
зависимостей при каждом запуске: сначала один раз вручную выполните
`run.bat`, чтобы создать `venv\` и `local.env.bat`, и только потом
регистрируйте задачу.

### 4. Доверить сертификат на рабочих машинах инженеров (только для самоподписанного)

На каждой клиентской машине (или централизованно через GPO,
`Computer Configuration → Windows Settings → Security Settings →
Public Key Policies → Trusted Root Certification Authorities`):

```powershell
Import-Certificate -FilePath "\\fileserver\it\cert.pem" -CertStoreLocation Cert:\LocalMachine\Root
```

Если вместо этого получится сертификат от внутреннего CA компании — этот
шаг не нужен, машины в домене уже доверяют корневому CA.

## Что стоит сделать перед реальной эксплуатацией

- Заменить `X-API-Key` на интеграцию с AD/LDAP или Windows Integrated
  Authentication (штатная возможность на внутреннем IIS/reverse proxy) —
  тогда `acknowledged_by` в `/api/ack` можно будет брать из
  аутентифицированной сессии, а не из текстового поля, которое инженер
  вписывает сам.
- HTTPS (внутренний CA компании подойдёт, необязательно публичный).
- Настроить в GPO домашнюю страницу/закреплённую вкладку браузера на
  `/status/?segment=...` для рабочих мест соответствующих сегментов.
